P046 [Heading 1] Project Title
P047 [Normal] COVAI – Software Testing and AI Chatbot Trustworthiness Evaluation System
P048 [Heading 1] Project Overview
P049 [Normal] COVAI is an AI-driven software quality platform that combines two complementary capabilities in a single engineering workflow. The first capability analyzes automated software testing by ingesting source code, detecting supported testing frameworks, executing tests in isolated environments, analyzing coverage and code structure, and generating additional tests. The second capability evaluates the trustworthiness of an internal AI chatbot according to project-specific knowledge, business rules, API contracts, conversation context and tool permissions.
P050 [Normal] The platform is intended for developers, QA engineers and AI engineers who need repeatable evidence about software quality. COVAI supports local ZIP uploads and GitHub repositories, project snapshots, background jobs, dashboards and notifications. The platform initially focuses on JavaScript/TypeScript projects and supported testing frameworks such as Jest, Vitest, Supertest, Playwright and Cypress.
P051 [Heading 1] Project Background and Motivation
P052 [pdq2pg_selectionanchorcontainer] Software testing is essential for ensuring software quality, but as projects become larger and more complex, developers face increasing difficulties in writing, executing, and maintaining automated tests. They often need to manually analyze test coverage, identify insufficiently tested code, understand code complexity, and create additional test cases.
P053 [Normal (Web)] Modern projects may also use different testing levels and frameworks, such as Unit, Integration, and System Testing with Jest, Vitest, Supertest, Playwright, or Cypress. This makes automated framework detection, test execution, and result analysis important challenges.
P054 [Normal (Web)] At the same time, many applications integrate AI chatbots for knowledge assistance, user guidance, and tool-based actions. These chatbots must be evaluated not only for answer correctness, but also for relevance, context retention, safety, privacy, and compliance with project-specific rules.
P055 [Normal] Motivation:
P056 [List Paragraph] Reduce manual effort in software testing and coverage analysis. 
P057 [List Paragraph] Identify insufficiently tested and complex source-code areas. 
P058 [List Paragraph] Use AI to assist in generating additional test cases. 
P059 [List Paragraph] Support multiple testing levels and frameworks in one platform. 
P060 [List Paragraph] Evaluate internal AI chatbots using project-specific knowledge and rules. 
P061 [List Paragraph] Provide measurable results and recommendations for improving software and chatbot quality. 
P062 [List Paragraph] Automate analysis through GitHub integration.
P063 [Heading 1] Problem Statement
P064 [Normal] Modern software teams face two related quality problems. First, automated testing is distributed across different testing levels and frameworks. Developers must manually execute tests, inspect coverage reports, identify insufficiently tested code, understand complex control flow, and create additional tests. These activities become increasingly time-consuming as projects grow and change frequently.
P065 [Normal] Second, web applications are increasingly integrating internal AI chatbots for question answering, user guidance, and tool or API-based actions. The reliability of these chatbots cannot be determined only by the name of the underlying model. Their behavior also depends on system prompts, internal data, retrieval mechanisms, conversation context, tool permissions, refusal logic, and implementation choices. Two chatbots that use the same model may therefore produce different levels of reliability.
P066 [Normal] A general-purpose comparison of large AI models is too broad for this project because different tasks require different evaluation criteria and many open-ended prompts do not have a single ground-truth answer. In contrast, an internal chatbot operates inside a specific application where source code, business documents, knowledge bases, API specifications, and confirmed business rules can provide project-specific ground truth.
P067 [Normal] Therefore, COVAI addresses the need for a unified engineering platform that can analyze software testing quality and also evaluate whether an internal AI chatbot behaves correctly, faithfully, safely, consistently, and appropriately within the data and business rules of its own web application.
P068 [Heading 1] Proposed Solution
P069 [Normal (Web)] COVAI is an AI-driven software quality platform that combines automated software testing and code analysis with AI chatbot trustworthiness evaluation in a unified engineering workflow.
P070 [Normal (Web)] The system accepts source code through local ZIP upload or GitHub repository import. After a project is imported, COVAI creates a source-code snapshot and analyzes the project configuration to identify the supported testing framework.
P071 [Normal (Web)] For software testing, COVAI executes tests inside isolated Docker environments and collects test results, execution logs, and coverage reports. Coverage is analyzed at overall, file, and function levels. The system also analyzes source-code structure using Control Flow Graph (CFG) and Cyclomatic Complexity to identify complex and insufficiently tested areas.
P072 [Normal (Web)] When testing gaps are identified, the AI service analyzes the source code, test results, coverage information, and code structure to generate additional test skeletons or test implementations. Generated tests can then be reviewed and validated by the user.
P073 [Normal (Web)] For AI chatbot evaluation, COVAI uses project-specific knowledge, business rules, API specifications, and expected behaviors to build an evaluation profile and generate benchmark scenarios. The system evaluates internal chatbots across tasks such as Knowledge Q&A, Usage Guidance, and Action/Tool Execution. Evaluation results include criteria such as correctness, faithfulness, relevance, consistency, context retention, safety, privacy, appropriate refusal, and tool usage.
P074 [Normal] Core Components:
P075 [List Paragraph] Project Management & Source Ingestion: Manages projects, source-code snapshots, ZIP uploads, and GitHub repository imports. 
P076 [List Paragraph] Test Execution & Coverage Analysis: Detects supported testing frameworks, executes tests in isolated Docker environments, and collects and analyzes coverage reports. 
P077 [List Paragraph] Code Structure Analysis: Analyzes source code using Control Flow Graph and Cyclomatic Complexity. 
P078 [List Paragraph] AI Test Generation: Uses AI to generate test skeletons and full test implementations based on source code and analysis results. 
P079 [List Paragraph] Multi-Framework Testing: Supports selected testing levels and frameworks, including Jest, Vitest, Supertest, Playwright, and Cypress. 
P080 [List Paragraph] AI Chatbot Trustworthiness Evaluation: Builds project-specific evaluation profiles, generates benchmark scenarios, evaluates chatbot responses and actions, and calculates trustworthiness scores. 
P081 [List Paragraph] Evidence, Dashboard & Reporting: Stores test and evaluation evidence and provides visual reports, scores, failed cases, risk indicators, recommendations, and job status. 
P082 [List Paragraph] GitHub Automation: Integrates with GitHub to import repositories and trigger analysis when source code is updated.

P252 [Heading 1] Conclusion
P253 [Normal] COVAI is designed as a unified software-quality platform with two major capabilities: automated software testing and AI chatbot trustworthiness evaluation. The software-testing pipeline helps developers move from source-code ingestion to test execution, coverage analysis, structural analysis and AI-assisted test generation. R06: NFR-05 || Performance || Long-running analysis shall use background jobs and shall provide progress/status feedback rather than blocking the user interface.
R07: NFR-06 || Modularity || The chatbot evaluation framework shall support adding new task-specific evaluation modules in future versions without redesigning the entire platform.
R08: NFR-07 || Usability || Evaluation results shall explain component scores, failed cases, expected behavior, observed behavior, and recommended next steps in a form understandable to developers and evaluators.
R09: NFR-08 || Safety || Evaluation of tool/action chatbots shall avoid unintended real-world side effects by using confirmation rules and controlled test environments when necessary.
