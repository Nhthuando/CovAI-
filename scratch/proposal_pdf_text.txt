1. Project Title 
COVAI – Software Testing and AI Chatbot Trustworthiness Evaluation System 
2. Project Overview 
COVAI is an AI -driven software quality platform that combines two 
complementary capabilities in a single engineering workflow. The first capability 
analyzes automated software testing by ingesting source code, detecting supported 
testing frameworks, execut ing tests in isolated environments, analyzing coverage and 
code structure, and generating additional tests. The second capability evaluates the 
trustworthiness of an internal AI chatbot according to project -specific knowledge, 
business rules, API contracts, conversation context and tool permissions. 
The platform is intended for developers, QA engineers and AI engineers who need 
repeatable evidence about software quality. COVAI supports local ZIP uploads and 
GitHub repositories, project snapshots, background jobs, dashboards and notifications. 
The platform initially focuses on JavaScript/TypeScript projects and supported testing 
frameworks such as Jest, Vitest, Supertest, Playwright and Cypress. 
3. Project Background and Motivation 
Software testing is essential for ensuring software quality, but as projects become 
larger and more complex, developers face increasing difficulties in writing, executing, 
and maintaining automated tests. They often need to manually analyze test coverage, 
identify insufficiently tested code, understand code complexity, and create additional 
test cases. 
Modern projects may also use different testing levels and frameworks, such as Unit, 
Integration, and System Testing with Jest, Vitest, Supertest, Playwright, or Cypress. 
This makes automated framework detection, test execution, and result analysis 
important challenges. 
At the same time, many applications integrate AI chatbots for knowledge assistance, 
user guidance, and tool -based actions. These chatbots must be evaluated not only for 
answer correctness, but also for relevance, context retention, safety, privacy, and 
compliance with project-specific rules. 
Motivation: 
o Reduce manual effort in software testing and coverage analysis.

4. Problem Statement 
Modern software teams face two related quality problems. First, automated testing 
is distributed across different testing levels and frameworks. Developers must manually 
execute tests, inspect coverage reports, identify insufficiently tested code, understa nd 
complex control flow, and create additional tests. These activities become increasingly 
time-consuming as projects grow and change frequently. 
Second, web applications are increasingly integrating internal AI chatbots for 
question answering, user guidance, and tool or API -based actions. The reliability of 
these chatbots cannot be determined only by the name of the underlying model. Their 
behavior also depends on system prompts, internal data, retrieval mechanisms, 
conversation context, tool permissions, refusal logic, and implementation choices. Two 
chatbots that use the same model may therefore produce different levels of reliability. 
A general -purpose comparison of large AI models is too broad for this project 
because different tasks require different evaluation criteria and many open -ended 
prompts do not have a single ground -truth answer. In contrast, an internal chatbot 
operates insi de a specific application where source code, business documents, 
knowledge bases, API specifications, and confirmed business rules can provide project-
specific ground truth. 
Therefore, COVAI addresses the need for a unified engineering platform that can 
analyze software testing quality and also evaluate whether an internal AI chatbot 
behaves correctly, faithfully, safely, consistently, and appropriately within the data and 
business rules of its own web application.

5. Proposed Solution 
COVAI is an AI-driven software quality platform that combines automated software 
testing and code analysis  with AI chatbot trustworthiness evaluation  in a unified 
engineering workflow. 
The system accepts source code through local ZIP upload or GitHub repository 
import. After a project is imported, COVAI creates a source-code snapshot and analyzes 
the project configuration to identify the supported testing framework. 
For software testing, COVAI executes tests inside isolated Docker environments 
and collects test results, execution logs, and coverage reports. Coverage is analyzed at 
overall, file, and function levels. The system also analyzes source -code structure using 
Control Flow Graph (CFG)  and Cyclomatic Complexity  to identify complex and 
insufficiently tested areas. 
When testing gaps are identified, the AI service analyzes the source code, test 
results, coverage information, and code structure to generate additional test skeletons or 
test implementations. Generated tests can then be reviewed and validated by the user. 
For AI chatbot evaluation, COVAI uses project-specific knowledge, business rules, 
API specifications, and expected behaviors  to build an evaluation profile and generate 
benchmark scenarios. The system evaluates internal chatbots across tasks such as 
Knowledge Q&A, Usage Guidance, and Action/Tool Execution . Evaluation results 
include criteria such as correctness, faithfulness, relevance, consistency, context 
retention, safety, privacy, appropriate refusal, and tool usage. 
Core Components: 
o Project Management & Source Ingestion:  Manages projects, source -code 
snapshots, ZIP uploads, and GitHub repository imports.  
o Test Execution & Coverage Analysis:  Detects supported testing frameworks, 
executes tests in isolated Docker environments, and collects and analyzes 
coverage reports.  
o Code Structure Analysis:  Analyzes source code using Control Flow Graph and 
Cyclomatic Complexity.  
o AI Test Generation:  Uses AI to generate test skeletons and full test 
implementations based on source code and analysis results.

12. Development Methodology and Technology Stack 
12.1 Development Methodology (Agile Scrum) 
We will follow an Agile Scrum methodology to develop the CovAI platform 
through iterative and incremental sprints. Each sprint focuses on implementing and 
integrating a specific group of system features. 
Scrum is suitable for this project because the system contains multiple technical 
components including backend services, frontend interfaces, Docker-based execution, 
code analysis, AI integration, and testing frameworks. 
The iterative development process allows the team to implement core functionality 
first, evaluate the results, identify technical problems, and gradually expand the 
system.

4. Problem Statement 
• Background of the problem: 
Software quality assurance relies heavily on comprehensive testing across multiple 
application layers (Unit, Integration, and System/E2E). As software applications become 
increasingly complex, maintaining high test coverage remains a primary defense against bugs 
and security vulnerabilities. Modern software engineering teams adopt Continuous 
Integration and Continuous Deployment (CI/CD) practices to deliver features rapidly. 
However, ensuring that code changes are properly verified across all testing layers  without 
slowing down deployment pipelines remains a critical challenge. At the same time, web 
applications are increasingly integrating internal AI chatbots for knowledge assistance, user 
guidance, and tool/API-based actions. The reliability of these chatbots cannot be determined 
only by the name of the underlying model. Their behavior also depends on system prompts, 
internal data, retrieval mechanisms, conversation context, tool permissions, refusal logic, and 
implementation choices. Two chatbots that use  the same model may therefore produce 
different levels of reliability and require project -specific evaluation against verified ground -
truth. 
• Current limitations / gaps: 
− Passive Coverage Analytics:  Traditional coverage tools (e.g., Istanbul, NYC, Jacoco) 
operate strictly as passive monitors. They generate static numeric reports (uncovered 

===== PAGE 43 =====
 
3 | P a g e  
lines and branches) but offer no actionable remediation, leaving developers to manually 
decipher and write missing test cases. 
− Granularity Mismatch in AI Test Generators: Existing AI-assisted test generation tools 
focus almost exclusively on isolated Unit Tests. They fail to evaluate higher -tier 
integration levels (such as API endpoints, controller responses, and end -to-end user 
journeys), leaving critical architectural boundaries untested. 
− Lack of Closed-Loop Automation: Most coverage evaluation tools are disconnected from 
real-time development workflows. They lack execution-validated feedback loops that can 
automatically detect coverage drops during git push events, generate corrective tests, 
and verify their execution within isolated environments. 
− Absence of Project-Specific Chatbot Trustworthiness Verification (AI Reliability Focus):  
General-purpose comparisons of large AI models are too broad because different tasks 
require different evaluation criteria. In contrast, an internal chatbot operates inside a 
specific web application where source code, business documents, FAQ lists, and A PI 
specifications define the ground truth. There is currently a complete lack of automated, 
reusable testing systems that can verify whether an internal chatbot behaves correctly, 
faithfully, safely, consistently, and appropriately within the precise data boundaries and 
business rules of its own hosting application. 
• Target users / stakeholders: 
− Software Engineers & Developers:  Developers who require immediate, actionable 
feedback on untested code paths and automated test suggestions to meet rigorous code 
quality gates without manual overhead. 
− QA & Automation Engineers:  QA teams who need a consolidated multi -tier testing 
overview (Unit, Integration, E2E) and automated assistance in authoring complex API and 
system integration tests. 
− AI Engineers & Quality Assessors (AI Reliability Focus):  AI engineers who need 
automated, repeatable mechanisms to configure chatbot evaluation profiles, ingest business

• Design and implement an automated multi -tier coverage analysis pipeline integrated with 
GitHub Webhooks that dynamically detects project test ecosystems (Jest, Vitest, Supertest, 
Playwright, Cypress) and computes real -time runtime coverage metrics (Line/Br anch %, API 
Endpoint %, and Scenario Execution %) within 3 minutes of code push events. 
• Develop a targeted AI -driven test generation engine utilizing Abstract Syntax Tree (AST)

• Deliver an automated CI/CD remediation workflow and dashboard that tracks versioned

Requests containing generated test suites whenever a commit decreases overall rep ository

6. Proposed Solution 
• System overview 

===== PAGE 45 =====
 
5 | P a g e  
COVAI is a unified, AI -driven software quality engineering platform that combines two 
complementary, high -quality capabilities: automated software test execution/analysis and AI 
chatbot trustworthiness evaluation into a single, integrated development workflow. For software 
testing, COVAI ingests codebases (ZIP or GitHub), statically analyzes project structure to detect 
the testing framework, executes tests within isolated Sandbox Docker containers, and analyzes 
code coverage and structure (CFG, complexity). It then utilizes a self-healing AI loop to generate 
missing test cases. For AI chatbot evaluation, COVAI ingests business documents, FAQ lists, and 
API specifications to build a structured evaluation profile. It automatically designs benchmark 
scenarios across  multiple chatbot tasks (Knowledge Q&A, Usage Guidance, and Action/Tool 
Execution), runs automated conversational test scenarios, and scores the chatbot's responses 
using a combination of model-assisted (Gemini-as-a-Judge) and deterministic evaluations. 
• Key features: 
− Automated Ecosystem Detection:  Statically analyzes project manifests (package.json, 
configuration signatures) to identify existing testing frameworks across Unit (Jest, Vitest), 
Integration (Supertest, Playwright API), and System/E2E (Cypress, Playwright E2E) layers. 
− Isolated Multi-Tier Execution & Metrics Extraction:  Runs test suites inside lightweight, 
isolated Sandbox containers to capture true runtime coverage metrics (Line/Branch %, 
API Endpoint %, and Scenario Execution %). 
− AST-Based Context Extraction:  Parses AST structures to extract precise function 
signatures, DTOs, and uncovered line boundaries, minimizing token consumption while 
providing rich context for AI prompts. 
− Execution-Guided Self -Healing AI Loop:  Sends uncovered code contexts to LLMs to 
generate missing test cases, automatically runs the generated tests in the Sandbox, 
captures any runtime/syntax errors, and recursively prompts the LLM to fix failed 
assertions until a 100% execution pass rate is achieved. 
− Automated Pull Request Remediation:  Automatically creates formatted GitHub Pull 
Requests containing verified test suites when coverage falls below configured quality 
thresholds.

− Commit-SHA Snapshot Tracking:  Stores and visualizes historical coverage trends across 
commit SHAs, enabling side-by-side snapshot diffing on a centralized Web Dashboard. 
− Multi-Source Knowledge Ingestion & Profile Builder (AI Reliability Focus):  Ingests 
project-specific knowledge assets (TXT, PDF, FAQ tables, and OpenAPI specs) to construct 
a structured evaluation profile mapping out application rules, target chatbot capabilities, 
and expected user behavior. 
− Automated Benchmark Scenario Generator (AI Reliability Focus):  Automatically 
generates test prompts and scenarios categorized by chatbot tasks: Knowledge Q&A 
(retrieval validity), Usage Guidance (correct step -by-step UI sequence), and Action/Tool

− Multi-Configuration Version Comparison & Diagnostics (AI Reliability Focus):  Allows

different chatbot versions, configurations, or prompt designs, classifying failed 
conversational cases and suggesting targeted model improvements.

Explain how system addresses them: 
Performance: 
Running multi-tier test suites inside containers can introduce CI/CD pipeline latency. The system 
mitigates this by using lightweight Docker containers, enforcing strict execution timeouts (under 
3 minutes per push), and applying AST parsing to extract only relevant code signatures. For 
chatbot evaluation, multi-threaded prompt execution is decoupled using BullMQ/Redis 
background queues to prevent blocking user interfaces. 
Security & Privacy: 

===== PAGE 52 =====
 
12 | P a g e  
Executing unverified AI-generated code presents arbitrary code execution risks. All test 
executions are isolated within network-restricted, ephemeral Docker containers running with 
non-root privileges. To ensure data privacy, sensitive credentials, API keys, and PII are strictly 
scrubbed from source code and chatbot conversation histories before prompt payload 
construction. 
Scalability: 
High-frequency commit activity and large chatbot evaluation runs (consisting of hundreds of 
generated benchmark scenarios) can easily overload backend workers. An event-driven task 
queue (BullMQ/Redis) decouples incoming GitHub Webhooks and evaluation triggers from 
backend workers, enabling horizontal scaling of runner containers. 
Cost: 
Frequent Large Language Model (LLM) API calls risk high operational token expenses. The 
system constrains costs through AST-based context truncation (passing only uncovered code 
slices rather than whole files) and prompt caching/token minimization during chatbot 
evaluations. 
Maintainability: 
To prevent framework lock-in, the system follows a modular microservices architecture. The 
static parser, container runner, LLM provider, and chatbot evaluation adapter layers are 
decoupled via abstract interfaces, allowing seamless swapping between AI models (OpenAI, 
Gemini, Llama) or test runners without refactoring core business logic. 
Economic: 
Manual test writing and manual chatbot testing account for significant developer/QA labor 
costs. By automating multi-tier coverage analysis, generating ready-to-merge Pull Requests, and 
automatically verifying chatbot trustworthiness against business rules, the system lowers QA 
overhead by up to 30% and accelerates product release cycles. 
8.2 Global & Societal Impact 
• Cultural / Social impact 
Software development and AI teams are increasingly distributed across global time zones. 
By providing automated, objective quality enforcement and standardized test/chatbot 
evaluation via automated workflows, COVAI reduces communication friction, eliminate s quality 
disparities between remote teams, and fosters an engineering culture focused on safety and 
alignment. Furthermore, it builds public trust in AI applications by preventing rogue chatbot 
behaviors. 
• Environmental (Green IT)

13 | P a g e  
To reduce the carbon footprint associated with heavy cloud computing and LLM inference, 
the system enforces energy -efficient execution strategies. It optimizes compute utilization 
through local AST pre -processing, prompt caching, and ephemeral container de struction, 
minimizing redundant energy and data center resource consumption. 
• Economic impact 
Uncaptured software bugs and AI chatbot hallucinations cost the global IT industry billions 
annually in emergency hotfixes, customer churn, and legal liabilities. By enforcing multi -tier

8.3 Ethical Considerations 
• Data privacy 
The system strictly enforces a zero -trust data pipeline. Proprietary source code and chatbot 
transcripts are never stored permanently on third-party AI servers. All environment variables, API 
tokens, and sensitive data are scrubbed before payload construct ion. Only anonymized AST 
structures and cleaned chatbot responses are transmitted to the evaluation API. 
• AI bias / fairness 
AI models may exhibit bias toward specific coding styles or evaluation parameters. COVAI 
addresses this by employing framework -specific prompt templates, utilizing deterministic 
validator rules where objective evidence exists, and calibrating LLM -as-a-judge scoring by 
comparing automated judgments against human/domain-expert judgments on a representative 
subset. 
• Intellectual property 
All test scripts and evaluation benchmark datasets generated by the system become the 
exclusive intellectual property of the project owner. The system relies on permissively licensed 
open-source test runners (Jest, Supertest, Cypress) and ensures that generated test suites do not 
inject copyrighted external dependencies into the target codebase.

1. Purpose of the Policy 
This policy establishes guidelines for the responsible, transparent, and ethical use of 
Artificial Intelligence (AI) tools in Software Engineering Capstone projects. 
The objectives are to: 
1. Encourage productive and responsible use of AI tools in software development. 
2. Ensure academic integrity and originality of student work. 
3. Prevent misuse of AI that results in superficial or unverified project outcomes. 
4. Ensure that students demonstrate genuine technical competence and understanding. 
5. Maintain the academic and professional standards expected from a university-level 
engineering capstone project. 
AI tools are recognized as legitimate development aids; however, students remain fully 
responsible for the intellectual and technical content of their projects.

• All students enrolled in: 
o Software Engineering 
o Management Information Systems 
o Related computing programs 
• All phases of the project lifecycle: 
o Proposal

o Implementation
