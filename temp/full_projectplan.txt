1. Introduction  
1.1. Purpose  
The purpose of this document is to provide a comprehensive project management 
and development plan for the COVAI – Software Testing and AI Chatbot 
Trustworthiness Evaluation System.  
This document defines the project organization, team responsibilities, 
communication methods, development methodology, implementation schedule, 
resource allocation, risk management, and project deliverables.  
The project plan serves as a guideline for the COVAI development team to 
coordinate activities, monitor project progress, manage technical risks, and ensure that 
the project is completed within the planned academic schedule.  
The main goal is to successfully develop an AI -driven software quality platform that 
supports automated software testing, test coverage analysis, code structure analysis, AI -
assisted test generation, and project -specific evaluation of internal AI chatbot 
trustworthiness.  
1.2. Project Overview  
The detailed project background, problem statement, proposed solution, system 
scope, architecture, functional requirements, and non -functional requirements are 
defined in:  
C1SE.30_Proposal_ver1.2.docx  
o COVAI is an AI -driven software quality platform that provides two major 
capabilities:  
o Software Testing and Quality Analysis: source -code ingestion, testing -
framework detection, isolated test execution, coverage analysis, Control Flow 
Graph analysis, Cyclomatic Complexity analysis, and AI -assisted test 
generation.  
o AI Chatbot Trustworthiness Evaluation: project -specific evaluation of internal 
AI chatbots using business rules, knowledge bases, API specifications, expected 
behaviors, and measurable trustworthiness criteria.  
o COVAI initially focuses on JavaScript/TypeScript projects and supports 
selected testing frameworks including Jest, Vitest, Supertest, Playwright, and 
Cypress.

3. Development  
 
The COVAI project follows the Agile Scrum methodology with iterative and 
incremental development.  
The project contains several interdependent technical components, including 
frontend interfaces, backend APIs, Docker -based test execution, source -code analysis, 
multiple testing frameworks, AI -assisted test generation, GitHub automation, and AI 
chatbot tr ustworthiness evaluation.  
Therefore, the system is divided into manageable development Sprints. Each Sprint 
defines a specific goal and produces an increment that can be tested, reviewed, and 
improved before proceeding to the next phase.  
Scrum Activities : 
o Product Backlog: Stores project requirements, user stories, technical tasks and 
research tasks.  
o Sprint Planning: Selects backlog items and defines the Sprint Goal.  
o Development: Implements frontend, backend, testing, AI and integration tasks.  
o Daily Scrum: Tracks current progress and blockers.  
o Testing: Tests completed functionality during each Sprint.  
o Sprint Review: Demonstrates completed features.
