P97 [Heading 1]: Project Title
P98 [Normal]: COVAI – Software Testing and AI Chatbot Trustworthiness Evaluation System
P99 [Heading 1]: Project Overview
P100 [Normal]: COVAI is an AI-driven software quality platform that combines two complementary capabilities in a single engineering workflow. The first capability analyzes automated software testing by ingesting source code, detecting supported testing frameworks, executing tests in isolated environments, analyzing coverage and code structure, and generating additional tests. The second capability evaluates the trustworthiness of an internal AI chatbot according to project-specific knowledge, business rules, API contracts, conversation context and tool permissions.
P101 [Normal]: The platform is intended for developers, QA engineers and AI engineers who need repeatable evidence about software quality. COVAI supports local ZIP uploads and GitHub repositories, project snapshots, background jobs, dashboards and notifications. The platform initially focuses on JavaScript/TypeScript projects and supported testing frameworks such as Jest, Vitest, Supertest, Playwright and Cypress.
P102 [Heading 1]: Project Background and Motivation
P103 [pdq2pg_selectionanchorcontainer]: Software testing is essential for ensuring software quality, but as projects become larger and more complex, developers face increasing difficulties in writing, executing, and maintaining automated tests. They often need to manually analyze test coverage, identify insufficiently tested code, understand code complexity, and create additional test cases.
P104 [Normal (Web)]: Modern projects may also use different testing levels and frameworks, such as Unit, Integration, and System Testing with Jest, Vitest, Supertest, Playwright, or Cypress. This makes automated framework detection, test execution, and result analysis important challenges.
P105 [Normal (Web)]: At the same time, many applications integrate AI chatbots for knowledge assistance, user guidance, and tool-based actions. These chatbots must be evaluated not only for answer correctness, but also for relevance, context retention, safety, privacy, and compliance with project-specific rules.
P106 [Normal]: Motivation:
P107 [List Paragraph]: Reduce manual effort in software testing and coverage analysis. 
P108 [List Paragraph]: Identify insufficiently tested and complex source-code areas. 
P109 [List Paragraph]: Use AI to assist in generating additional test cases. 
P110 [List Paragraph]: Support multiple testing levels and frameworks in one platform. 
P111 [List Paragraph]: Evaluate internal AI chatbots using project-specific knowledge and rules. 
P112 [List Paragraph]: Provide measurable results and recommendations for improving software and chatbot quality. 
P113 [List Paragraph]: Automate analysis through GitHub integration.
P114 [Heading 1]: Problem Statement
P115 [Normal]: Modern software teams face two related quality problems. First, automated testing is distributed across different testing levels and frameworks. Developers must manually execute tests, inspect coverage reports, identify insufficiently tested code, understand complex control flow, and create additional tests. These activities become increasingly time-consuming as projects grow and change frequently.
P116 [Normal]: Second, web applications are increasingly integrating internal AI chatbots for question answering, user guidance, and tool or API-based actions. The reliability of these chatbots cannot be determined only by the name of the underlying model. Their behavior also depends on system prompts, internal data, retrieval mechanisms, conversation context, tool permissions, refusal logic, and implementation choices. Two chatbots that use the same model may therefore produce different levels of reliability.
P117 [Normal]: A general-purpose comparison of large AI models is too broad for this project because different tasks require different evaluation criteria and many open-ended prompts do not have a single ground-truth answer. In contrast, an internal chatbot operates inside a specific application where source code, business documents, knowledge bases, API specifications, and confirmed business rules can provide project-specific ground truth.
P118 [Normal]: Therefore, COVAI addresses the need for a unified engineering platform that can analyze software testing quality and also evaluate whether an internal AI chatbot behaves correctly, faithfully, safely, consistently, and appropriately within the data and business rules of its own web application.

P121 [Heading 1]: Proposed Solution
P122 [Normal (Web)]: COVAI is an AI-driven software quality platform that combines automated software testing and code analysis with AI chatbot trustworthiness evaluation in a unified engineering workflow.
P123 [Normal (Web)]: The system accepts source code through local ZIP upload or GitHub repository import. After a project is imported, COVAI creates a source-code snapshot and analyzes the project configuration to identify the supported testing framework.
P124 [Normal (Web)]: For software testing, COVAI executes tests inside isolated Docker environments and collects test results, execution logs, and coverage reports. Coverage is analyzed at overall, file, and function levels. The system also analyzes source-code structure using Control Flow Graph (CFG) and Cyclomatic Complexity to identify complex and insufficiently tested areas.
P125 [Normal (Web)]: When testing gaps are identified, the AI service analyzes the source code, test results, coverage information, and code structure to generate additional test skeletons or test implementations. Generated tests can then be reviewed and validated by the user.
P126 [Normal (Web)]: For AI chatbot evaluation, COVAI uses project-specific knowledge, business rules, API specifications, and expected behaviors to build an evaluation profile and generate benchmark scenarios. The system evaluates internal chatbots across tasks such as Knowledge Q&A, Usage Guidance, and Action/Tool Execution. Evaluation results include criteria such as correctness, faithfulness, relevance, consistency, context retention, safety, privacy, appropriate refusal, and tool usage.
P127 [Normal]: Core Components:
P128 [List Paragraph]: Project Management & Source Ingestion: Manages projects, source-code snapshots, ZIP uploads, and GitHub repository imports. 
P129 [List Paragraph]: Test Execution & Coverage Analysis: Detects supported testing frameworks, executes tests in isolated Docker environments, and collects and analyzes coverage reports. 
P130 [List Paragraph]: Code Structure Analysis: Analyzes source code using Control Flow Graph and Cyclomatic Complexity. 
P131 [List Paragraph]: AI Test Generation: Uses AI to generate test skeletons and full test implementations based on source code and analysis results. 
P132 [List Paragraph]: Multi-Framework Testing: Supports selected testing levels and frameworks, including Jest, Vitest, Supertest, Playwright, and Cypress. 
P133 [List Paragraph]: AI Chatbot Trustworthiness Evaluation: Builds project-specific evaluation profiles, generates benchmark scenarios, evaluates chatbot responses and actions, and calculates trustworthiness scores. 
P134 [List Paragraph]: Evidence, Dashboard & Reporting: Stores test and evaluation evidence and provides visual reports, scores, failed cases, risk indicators, recommendations, and job status. 
P135 [List Paragraph]: GitHub Automation: Integrates with GitHub to import repositories and trigger analysis when source code is updated.

P307 [Heading 2]: Development Methodology (Agile Scrum)
P308 [Normal]: We will follow an Agile Scrum methodology to develop the CovAI platform through iterative and incremental sprints. Each sprint focuses on implementing and integrating a specific group of system features.
P309 [Normal]: Scrum is suitable for this project because the system contains multiple technical components including backend services, frontend interfaces, Docker-based execution, code analysis, AI integration, and testing frameworks.
P310 [Normal]: The iterative development process allows the team to implement core functionality first, evaluate the results, identify technical problems, and gradually expand the system.

P368 [Heading 1]: Conclusion
P369 [Normal]: COVAI is designed as a unified software-quality platform with two major capabilities: automated software testing and AI chatbot trustworthiness evaluation. The software-testing pipeline helps developers move from source-code ingestion to test execution, coverage analysis, structural analysis and AI-assisted test generation. The AI-evaluation pipeline complements this by checking whether an internal chatbot behaves according to project-specific facts, rules, context and action constraints.
P370 [Normal]: The combination of project snapshots, background jobs, evidence collection, configurable evaluation profiles and reporting provides a basis for repeatable quality assessment. At the same time, the project explicitly recognizes the limits of AI-generated tests and model-assisted evaluation, so critical results remain subject to validation and domain-expert review.
P371 [Normal]: The expected result is a functional academic prototype that demonstrates how software testing quality and AI-powered application behavior can be evaluated in one engineering workflow.
