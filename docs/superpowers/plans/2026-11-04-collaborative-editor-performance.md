# Collaborative editor performance follow-up

User authorizes implementation to address slow open and accumulating remote typing lag. Preserve English UI, existing surfaces, durability, authorization, recovery and canonical writer coordination. Work inline, no delegation.

Observed bottlenecks: client per-keystroke FIFO/one durable RTT per entry and debounce reset on every key; cursor/presence DB roundtrips and exclusive project locks; duplicate authorization/document reads; per-recipient fanout transactions; unbundled Monaco dev imports. Do not claim multi-server support just by adding a Redis adapter.

Delivery:
- [x] Measure baseline: burst typing with injected persistence latency; actual browser Monaco/worker smoke and SQL open timing; bounded read-only Railway roundtrip probe.
- [x] Merge unsent Yjs updates with a stable request ID per sent batch, throttle rather than debounce; never mutate an in-flight/retried batch. Preserve recovery and flush.
- [x] Optimize durable update store using bounded SQL under shared project / exclusive document locks, current authorization and atomic state/provenance/receipt persistence. Different files can proceed concurrently; membership/checkpoint remains exclusive.
- [x] Ack persisted updates without waiting for recipient fanout. Batch fanout authorization in one shared guard. Cursor/presence use authenticated opened scopes with immediate revocation invalidation and periodic revalidation; no source content on the ephemeral channel.
- [x] Reduce redundant open and access polling; prebundle Monaco while excluding worker entries. Verify actual browser workers and no blank page regression.
- [x] Focused permission/concurrency/retry/queue tests, burst timing before/after and actual Monaco two-client convergence. Build/lint; update runbook. Do not edit user source for benchmarks.

Research: https://docs.yjs.dev/api/document-updates (mergeUpdates); https://socket.io/docs/v4/emitting-events (acknowledgments and volatile ephemeral events); https://www.prisma.io/docs/orm/v7/prisma-client/queries/transactions (short transactions); https://socket.io/docs/v4/adapter (multi-server coordination is separate from local throughput).

Measurement limits: fixture store latency and local browser timings are not production throughput; report remote database distance honestly. No before-commit source broadcast or optimistic Saved label.


Verified implementation and evidence (2026-11-04):
- Pending unsent updates merge; sent request ID/bytes remain immutable across retry and recovery. Fixed 40 ms scheduling, compacted legacy backlog, 50 ms volatile cursors. Cursor packets no longer carry the opened document state, and recovery no longer serializes that redundant binary snapshot per key.
- One authenticated shared transport per account, reference-counted listeners and heartbeat. Pre-open buffering plus bounded committed-delta catch-up handles writes racing file open. Coalesced sync cannot apply stale responses to a replacement document.
- Hot durable write is one atomic SQL statement with current writer membership, project shared/document exclusive advisory locks, revision/generation CAS, state/provenance/receipt persistence and authorized recipient list. Cache eviction and stale-authority fallback retain correctness. Unknown/new recipients are reauthorized before source delivery; cached open capability alone never grants source access. Bounds: 128 documents/32 MiB accepted-state cache; 128 documents/16 MiB catch-up cache; 64 reads/8 MiB short canonical-read cache.
- Canonical GET and existing-document open each measured one SQL query; first-ever version initialization two queries, first document creation one query. Fast-path gates recheck access/workspace stamps and current membership; fallback retains filesystem recovery and canonical writer coordination. Snapshot creation bumps workspace revision.
- Deferred first mount of hidden dashboards preserves their state after visiting. Monaco is prebundled with worker entry exclusions. Access polling relaxed to 15 seconds; realtime access invalidation retained.

Measurements (controlled fixture, not production capacity):
- Actual two-browser Monaco typing, 60 keys at 10 ms intervals, injected 300 ms durable write delay: legacy 60 writes / p50 10,213 ms / p95 18,194 ms / final typing lag 18,769 ms; optimized 4 writes / p50 471 ms / p95 620 ms / final lag 360 ms. Both peers converge to identical final text.
- Authorized Railway dev/test connection, private TEMP tables only: SELECT 1 318-322 ms, cold durable write 674 ms (2 queries), warm 326 ms (1 query), canonical read 331 ms, existing open 331 ms, first file read 648 ms, first open 332 ms. Temporary tables and temporary local source are removed; public project tables untouched.
- SQL checks: owner/dev, replay, viewer denial, recipient filtering, downgrade both with and without epoch bump, forged project, stale generation, atomic rollback, compatible shared locks and excluded checkpoint lock. Actual Prisma binary/array/JSON codec checked separately.
- Focused final Jest selection: 62 passed, 15 pre-existing gated integration tests skipped (7 passing suites, 3 skipped). Client build and scoped lint pass. Layout has unchanged baseline lint findings (2 errors, 2 warnings); full-repository lint is not claimed clean.
- Actual Monaco with PM/Dev/Viewer under StrictMode passes edit/read-only, two-way convergence, file switching with transport reuse and update-before-open-ack regression. Hook auth/scope/retained-panel checks and landing render pass; zero landing page errors. Full logged-in E2E remains user-owned.

Evidence scripts: outputs/collaboration-burst-benchmark.mjs (--legacy for before), collaboration-sql-performance.mjs, collaboration-prisma-codec-check.mjs, collaboration-live-regression.mjs (--early), collaboration-hook-regression.mjs and collaboration-render-smoke.mjs. Run browser fixtures sequentially to avoid artificial Chromium resource exhaustion.

Limits: durable source fanout waits for committed storage; remote DB RTT is a floor. These changes target the current single API instance. Multiple API instances still need a cross-node Socket.IO adapter, cross-node membership/reset notifications and distributed convergence verification before claiming support. No multi-user capacity or production latency SLA was load-tested. No migration required for this follow-up.

Save follow-up (2026-11-04)
- Scope: reduce actual Save completion time without changing checkpoint semantics or UI. Keep exclusive project locking, fresh post-lock permission/snapshot/revision checks, fsync journal/backup and transaction rollback. Do not mark Saved before publication commit.
- Implemented one-query authorized checkpoint preflight and one-query status metadata (no document state payload). Checkpoint guard loads role, snapshot/latest snapshot and all requested revision/base-version metadata together after acquiring the project lock. Batched final CTE updates file versions, attribution, checkpoint revisions, workspace revision, mutation receipt and persisted project event atomically. SQL roundtrips do not grow with file count. Other publication flows retain their existing callbacks and behavior.
- Only the selected file is flushed for a single-file Save; operations saving the whole snapshot flush all matching providers in parallel. Save returns after commit/cleanup; authorized subscriber notifications run after commit without blocking the HTTP response. Persisted project events remain available for catch-up.
- Railway private-TEMP-fixture measurement: 7 database roundtrips including BEGIN/COMMIT for a dirty file, 2,246-2,992 ms service time, status one query / 321-331 ms. Two-file checkpoint measured 2,216 ms with the same seven roundtrips, and both canonical files matched their drafts. These numbers exclude HTTP middleware/browser, pending local updates and concurrent lock waits. No before/after user-account timing is claimed.
- Verification: 30 focused Jest tests pass, including a regression that a deliberately unresolved subscriber notification cannot block durable Save completion. Real SQL fixture confirms canonical bytes, attribution, APPLIED receipt/event, View denial, repeated Save, edit/undo unchanged bytes, rollback on forced event insertion failure, journal byte restoration and successful retry. Actual browser Monaco/provider Save with synthetic HTTP checkpoint confirms current content and Saved to workspace status; two-way edits, Viewer read-only and file switching still pass. Client build/scoped lint and server syntax pass. No schema migration required; no public project data changed.


Line-history hover follow-up (2026-11-05)
- Bottleneck: each live hover resolved snapshot/access, canonical filesystem path, document/access again and author in sequential queries. Client keyed only the exact line and canceled useful work on mouse movement.
- Live editor history now uses one current-membership-scoped query with project/snapshot/document/path identity, active/generation/revision checks and joined change/actor provenance. No Yjs binary fetched; source text fetched only for unattributed Git fallback. Nearby authored ranges are clipped to +/-20 lines, allowing the client to reuse known neighbors without speculation or extra HTTP requests. Legacy non-live preview keeps its canonical version/path flow.
- Client cache bounded to 512 entries/5 seconds, account/token + project/snapshot/path/document/generation/revision keyed. Exact concurrent hovers share one bounded (5-second) request; cancellation does not discard a shared result. Reject stale model/scope/generation/revision/account responses. Unsynced local edits retain the Unsynced edit message. Cached authored neighbors are immediate; gaps remain unknown until actually queried.
- Git subprocess cache: 128 small results, 2-second TTL keyed canonical root/path/content hash/line, identical concurrent requests coalesce, at most four Git tasks per instance. Saturation returns retryable 503 instead of caching false missing provenance. Existing 2.5-second timeout, output cap, local .git check, literal pathspec and read-only flags remain.
- Real PostgreSQL private-TEMP-table measurement: line-history 283 ms / one query; authored response omits text. Verified Viewer read, outsider/wrong-path rejection, stale revision/generation rejection; no public data changes. Isolated browser actual hover module: neighboring line 1 ms / no additional API request; same-line pending coalescing and revision/account/stale-response guards pass. First lookup still includes remote DB/network/auth latency; unknown Git-backed lines may take longer. No many-user load capacity is claimed.
- Verification: focused editor/Git/protocol selection 15 tests passed, new history/Git selection five tests passed; scoped client lint and production build pass. Evidence: outputs/line-history-hover-regression.mjs, outputs/collaboration-sql-performance.mjs, server/src/tests/projectLineHistory.test.js. No migration required.
